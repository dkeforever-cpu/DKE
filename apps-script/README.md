# 구글 시트 + Apps Script 백엔드 배포 가이드

이 폴더의 5개 파일은 이 업무관리 시스템의 데이터베이스(구글 시트)와 파일 저장소(구글
드라이브)를 연결해주는 백엔드입니다. 별도 서버나 DB 가입 없이, 회사에서 이미 쓰고 있는
구글 계정만으로 전체 팀이 데이터를 공유할 수 있습니다.

## 1. 구글 시트 준비

1. [sheets.google.com](https://sheets.google.com) 에서 새 스프레드시트를 만듭니다.
   (이름은 자유롭게, 예: `DKE 업무관리 DB`)
2. 상단 메뉴에서 **확장 프로그램 → Apps Script** 를 클릭합니다.

## 2. 스크립트 파일 붙여넣기

Apps Script 편집기가 열리면:

1. 기본으로 생성된 `Code.gs` 파일의 내용을 전부 지웁니다.
2. 이 저장소의 `apps-script/` 폴더에 있는 5개 파일을 **파일명까지 동일하게** 하나씩
   만들어 내용을 그대로 붙여넣습니다 (편집기 왼쪽 `+` → 스크립트 → 파일명 입력):
   - `Sheets.gs`
   - `Code.gs`
   - `Handlers.gs`
   - `Drive.gs`
   - `Setup.gs`
3. 전체 저장 (Ctrl+S / Cmd+S).

## 3. 초기 설정 실행 (시트 생성 + 사용자 등록)

1. 편집기 상단의 함수 선택 드롭다운에서 `setup` 을 선택합니다.
2. **실행** 버튼(▶)을 클릭합니다.
3. 처음 실행하면 권한 승인 화면이 뜹니다:
   - 계정 선택 → "Google에서 확인하지 않은 앱" 경고가 보이면 **고급** → **(프로젝트
     이름)(으)로 이동 (안전하지 않음)** 클릭 → **허용**
   - 본인이 만든 스크립트이므로 안전합니다. 스프레드시트/드라이브 접근 권한만 요청합니다.
4. 실행이 끝나면 스프레드시트로 돌아가 `Users`, `Tasks`, `ChecklistItems`,
   `LogEntries`, `Comments` 5개 탭이 생성되고, `Users` 탭에 10명의 팀원이 채워진 것을
   확인합니다.
5. 팀원 구성이 다르다면 `Users` 탭을 직접 수정하세요 (열: `id`, `name`, `dept`,
   `isAdmin`). `dept` 는 `관리팀` 또는 `재경팀`, `isAdmin` 은 `TRUE`/`FALSE` 입니다.

## 4. 웹 앱으로 배포

1. 편집기 우측 상단 **배포 → 새 배포** 클릭.
2. 유형 선택(톱니바퀴)에서 **웹 앱** 선택.
3. 설정:
   - **실행할 사용자**: 나 (본인 계정)
   - **액세스 권한이 있는 사용자**: 전체
4. **배포** 클릭 → 다시 한번 권한 승인이 뜨면 3번과 동일하게 허용합니다.
5. 배포가 끝나면 `https://script.google.com/macros/s/...../exec` 형태의 **웹 앱 URL**이
   표시됩니다. 이 URL을 복사해두세요.

> ⚠️ 배포 시 "액세스 권한이 있는 사용자"를 반드시 **전체**로 설정해야 합니다. "나만"으로
> 설정하면 다른 팀원의 브라우저에서 이 앱에 접속할 수 없습니다. 브라우저에서 로그인 자체는
> 앱 화면에서 하는 것이 아니라 단순히 계정을 선택하는 방식이므로, 실제 접근 제어는 이 웹
> 앱 URL을 아는 사람만 쓸 수 있다는 점과 사내에서만 URL을 공유한다는 점으로 이루어집니다.

## 5. 업무관리 시스템에 연결

1. 업무관리 시스템 접속 → 로그인 화면(또는 우측 상단 톱니바퀴 아이콘)에서
   **데이터 연동 설정**을 엽니다.
2. 4번에서 복사한 웹 앱 URL을 붙여넣고 **연결 테스트**를 눌러 "연결 성공" 메시지를
   확인합니다.
3. **저장하고 새로고침**을 누르면 등록된 팀원 목록이 로그인 화면에 나타납니다.

이제 팀원 누구나 같은 URL을 입력해 같은 구글 시트/드라이브를 공유하는 업무관리
시스템을 사용할 수 있습니다.

## 6. 스크립트를 수정한 경우 재배포하는 방법

`apps-script/*.gs` 파일 내용을 바꿨다면, **배포 → 배포 관리** → 연필(수정) 아이콘 →
**버전: 새 버전** 선택 → **배포**. 웹 앱 URL은 그대로 유지되므로 팀원들이 다시 설정할
필요는 없습니다.

## 참고: 데이터 구조

- **Users**: 사용자 목록 (로그인용 계정)
- **Tasks**: 업무 (제목/분류/담당자/진행률 등)
- **ChecklistItems**: 업무별 "필요 업무" 체크리스트 (트리 구조, `parentId`로 상하위 연결)
- **LogEntries**: 업무별 진행 일지
- **Comments**: 체크리스트 항목/진행 일지에 달리는 댓글

첨부파일은 `apps-script/Drive.gs` 를 통해 구글 드라이브의 "DKE 업무관리 첨부파일"
폴더에 저장되고, 링크(anyone with the link) 공유로 팀원 누구나 열람할 수 있습니다.

## 참고: 로컬에서 직접 테스트하고 싶다면

이 백엔드는 구글 인프라 위에서만 실행되므로, 코드를 작성한 환경에서 직접 실행해 볼 수는
없습니다. 대신 `apps-script/*.gs` 와 완전히 동일한 `{action, payload} → {ok, data}`
API 계약을 검증하기 위해, 개발 중에는 동일한 계약을 구현한 로컬 Node.js 목(mock) 서버로
프론트엔드 연동 로직(설정 화면, 데이터 저장/수정/삭제, 파일 업로드, 새로고침 후 데이터
유지)을 Playwright로 자동 테스트했습니다. 실제 배포본은 위 1~5단계를 따라 본인 구글
계정으로 직접 배포한 뒤 테스트해주세요.
