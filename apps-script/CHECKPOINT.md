# 체크포인트: 최종 확정 버전 (2026-09-07, 2026-09-09 Excel 기능으로 갱신)

사용자가 실제 배포 환경(구글 앱스크립트 웹 앱)에서 아래 기능을 전부 확인하고
"현시점 최종 버전"으로 확정한 상태입니다.

## 포함된 기능
- 구글 시트를 DB로, 구글 드라이브를 파일 저장소로 쓰는 백엔드 연동
- 로그인 / 팀·게시판·카테고리 구조 / 업무 등록·상세·체크리스트·댓글
- 첨부파일(진행 일지·댓글) — 구글 드라이브 **직접 업로드** 방식(빠름):
  - `google.script.run`으로 업로드 세션 URL을 받아 브라우저가 드라이브에 직접 PUT
  - 그 응답을 브라우저가 못 읽어도(CORS) 서버가 세션 상태를 대신 확인해서
    파일 정보를 가져오는 방식으로 완전히 동작 확인됨 (`finalizeDirectUpload`)
  - 파일 크기 제한 20MB
- 첨부파일 삭제 시 즉시 삭제 대신 드라이브의 **"물류센터 업무관리 - 삭제예정"**
  폴더로 이동 (댓글 직접 삭제, 업무·체크리스트 삭제로 인한 연쇄 삭제 전부 포함)
- 가져오기(import) 시 기존 데이터 전체 교체 + 날짜 서식 깨짐 방지
- 앱 코드(App.html)에 실제 직원 이름/업무 내용이 담긴 시드 데이터 없음(제거됨)
- App.html은 esbuild `supported: {"template-literal": false}`로 빌드해
  백틱(`` ` ``) 문자를 아예 안 씀 — 앱스크립트 편집기에 큰 코드를 붙여넣을 때
  반복됐던 파싱 에러의 실제 원인이 백틱 문자 손상이었던 것으로 확인됨

## 하지 않기로 한 것 (시도했다가 되돌림 — 다시 시도하지 말 것)
- **`<?!= include(...); ?>` 스크립틀릿으로 App.html 자체를 조각내 합치기** —
  크기와 무관하게 실제 배포에서 파싱 에러가 반복 재현됐다(로컬 테스트로는
  재현 불가). App.html 본체는 앞으로도 계속 파일 하나로 유지한다.
- **깃허브 등 외부 저장소에서 코드를 받아와 서빙하기** — 사용자가 명시적으로
  거부(추출/이전 시 외부 의존성이 문제가 됨).

## Excel 내보내기 기능의 서식 라이브러리(exceljs) — 앱스크립트 프로젝트에
## 파일로 담지 않기로 함 (2026-09-09, 여러 방식 시도 후 결론)
Excel 다운로드 기능(관리자설정 → Excel)은 서식(테두리·배경색·병합) 지원을
위해 exceljs(최소화해도 800KB+)가 필요하다. 아래 방식들을 순서대로 시도했고
전부 실패해서, **앱스크립트 프로젝트에는 이 라이브러리를 아예 두지 않기로
결정했다**:
1. App.html에 직접 포함 → 배포 파일이 두 배 넘게 커짐 (시도 안 함, 처음부터 배제)
2. 별도 파일(`ExcelLib.html`) + `Code.gs`의 `doGet(?resource=exceljs)` +
   `<script src=...>`로 로드 → 실제 배포에서 항상 로드 실패
3. 위와 동일하되 `fetch()` + 인라인 `<script>` 실행으로 변경 → 로드는 되지만
   `HtmlService.createHtmlOutputFromFile()`이 순수 JS를 "형식이 잘못된 HTML
   콘텐츠"로 거부함
4. 파일 내용을 `<script>...</script>`로 감싸 저장 → 검증은 통과하지만, 실제
   배포에서 받아온 내용이 매번 전체의 약 1% 정도 손실됨(원인 특정 못 함 —
   구글 앱스스크립트의 파일 저장/처리 쪽 용량·처리 한계로 추정)
5. 파일을 절반씩 두 개로 나눠 저장 → 손실량이 그대로 재현됨(파일 크기
   문제가 아니라는 게 이때 확인됨)

**최종 해결책**: exceljs·FileSaver.js를 앱스크립트 프로젝트에 전혀 두지 않고,
App.html의 `<head>`에서 `<script defer src="https://cdnjs.cloudflare.com/...">`
로 CDN에서 직접 불러온다. 앱스크립트 저장 용량/검증 문제와 완전히 무관해지고,
App.html 자체 크기도 거의 그대로다(~425KB). `src/lib/exceljs-loader.ts`는
`window.ExcelJS`가 준비될 때까지 폴링만 하고, Next.js 개발 화면(layout.tsx)도
같은 CDN을 쓰도록 해서 개발/배포 양쪽이 동일한 코드 경로를 탄다.
